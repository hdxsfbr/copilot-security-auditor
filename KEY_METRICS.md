# Key metrics and evidence rules

Product claim: an authorized operator can repeatedly discover, substantiate and track Clinical Co-Pilot boundary failures across explicit target versions at a known operational cost. Each metric below tests part of that claim. Measured values are stated where they exist, with their source, sample size and limits. Where none exists the entry says so, and no value is estimated in this file.

## Definitions

| Metric | Definition and denominator | Why it proves success |
| --- | --- | --- |
| **Supported distinct findings** | Count unique, current-version, reproduced violations with complete action and evidence links and a reviewed or calibrated confirmation route. Report by category and severity; show pending and unsupported separately | Rewards useful discovery, not duplicate candidates or model assertions. Regression identity ([G01](apps/api/src/regression-identity.ts)) supplies the uniqueness |
| **Reproduction and fix verdict quality** | For each confirmed attack and version pair: reproduced with the same boundary and criterion divided by eligible completed replays; separately count `fixed`, `recurring`, `resurfaced`, `unknown`. Blocked and incomplete replays are never fixed or failed | A finding that cannot recur, or whose fix is inferred from wording, is not actionable. States are derived by a pure rule ([`regression-states.ts`](apps/api/src/regression-states.ts)) |
| **Judge calibration** | On a frozen labeled synthetic set, by policy and model version: false auto-confirm rate over safe, echo and refusal controls; false-safe rate over genuine violations; abstention over ambiguous cases. Record corpus size and an interval, never a bare percent | False confirmation and false assurance both destroy trust. Thresholds are set before live scoring; auto-confirm stays limited to one structural path until a gate is justified |
| **Versioned exercised coverage** | For target, version and window and category and subcategory: executed and assessable case definitions divided by eligible published definitions; also attempted, blocked, incomplete, adjudicated and untested counts. Safe-rate denominators exclude unknown evidence | Reveals blind spots and stops comparisons across unlike scopes ([V01](docs/implementation/scoped-coverage.md)) |
| **Assessable evidence** | Runs whose every observation is complete divided by executed runs | Separates auditor limits from target limits, so an `inconclusive` is not read as a defense |
| **Bounded operating cost and throughput** | Per run and role: settled provider charge, unresolved hold, reservation, tokens, latency. For 100-case fixture and authorized live runs: wall time, p50 and p95 latency, CPU and memory peak, queue age, incomplete rate. Actual development spend is reported separately | Shows continuous evaluation can run without hidden charge or backlog. The ledger and queue-age signal exist ([M02](docs/implementation/spend-reconciliation.md), [O01](README.md#operations-and-recovery)) |

Each chart or export must show sample size, target and version, case-definition version, evidence mode (black-box or approved read-only corroboration), time window and policy version. Comparing unlike scopes is not allowed. A rise in attempted cases or model calls is not success by itself. Target outcomes and human finding disposition are reported separately, and a confirmed finding never rewrites an execution's observed response.
