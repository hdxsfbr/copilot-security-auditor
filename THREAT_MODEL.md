# Clinical Co-Pilot adversarial threat model

## Executive summary

The Clinical Co-Pilot answers questions from the chart currently bound to an OpenEMR conversation. It accepts PDFs, cites records and can display guideline material. Its security promise is that lower-trust words in chat, notes, comments, excerpts or PDFs cannot change the patient, authorization scope, tools, output rules or write boundary. A clinician may legitimately open another patient's chart; the testable cross-patient promise is **chart-context isolation within the current Co-Pilot conversation**, not denial of separate chart access. The [feature brief](docs/COPILOT_FEATURE.md) describes the target; its source is not in this repository.

The highest-priority attack is a response presenting another patient's clinical facts as facts for the open chart. Direct instructions, retrieved text, a synthetic PDF or multi-turn manipulation could cause this. Repeating a patient identifier alone is not disclosure. A second priority is an unsolicited chart effect or false claim that an order or save occurred. The brief says the agent is read-only and only a clinician's explicit Save writes reviewed lab facts. The auditor's before/after patient-report hash sees only that report; unchanged bytes do not prove every module-owned table unchanged. A third priority is advice, unsupported claims or misleading provenance that could alter clinical decisions. These outcomes need claim-level evidence.

The auditor also holds synthetic credentials, transports attacker-controlled text, calls models, stores PDFs and can label a run safe or a finding confirmed. False confirmation wastes security effort; false safety hides a boundary failure. The September 28 [audit](docs/audit/2026-09-28/AUDIT.md) reproduced citation loss, silent truncation, an unsupported automatic confirmation and export after a linked PDF disappeared. These are verified **auditor defects**, not proof of a live Co-Pilot vulnerability. The audit also verified useful reservations, encrypted credential snapshots, lease fencing, cautious retries and spend accounting.

Testing starts with authorized synthetic identities and user-facing chat/PDF actions. The worker, never the attack model, controls endpoints, chart selection, credentials, tickets and replay. It should preserve response structure and completeness, link judgment to executed evidence, and route unsupported claims to review. The optional read-only evidence adapter may later add approved seeded facts and correlated audit events; it is disabled by default and grants no target-source or live access. Without it, broad write absence and cross-chart provenance may remain unknown. A fixture pass is not a live finding.

Coverage should expand from direct injection to indirect and multi-turn variants, negative controls, authorization/output boundaries, resource exhaustion and regressions. Each case needs target version, expected behavior, exact actions, evidence limits and OWASP mapping. The Orchestrator should select untested or high-risk gaps only after prior judgments are trustworthy. Confirmed exploits become versioned regressions; blocked, incomplete and inconclusive attempts never prove a defense. Human review handles uncertain findings and publication. Current evidence and planned controls remain separate as results arrive.

Priority follows potential clinical harm and the strength of available proof. When evidence cannot distinguish a plausible violation from a benign refusal or prompt echo, the result should stay unknown and direct the next synthetic test toward the missing fact.

## Assets, actors, entry points, and trust boundaries

| Asset or boundary | Lower-trust input / actor | Failure and impact | Current defense and evidence limit |
| --- | --- | --- | --- |
| Current-chart clinical facts and clinician decisions | User chat, chart notes/comments, PDF text, guideline excerpts | Cross-chart fact disclosure; unsupported citation or medical advice | Target brief promises server-bound chart, read-only tools, verifier and citations. Auditor currently loses structured source metadata; [E01](https://linear.app/hdxsfbr/issue/HDX-7) and [E03](https://linear.app/hdxsfbr/issue/HDX-10) own proof repair. |
| Target session and identity | Synthetic clinician credentials, cookies, CSRF, conversation ticket; model proposal | Wrong chart, role confusion, replay, cross-session contamination | Worker chooses saved identity and resolves exact `pubpid`; model cannot choose URL, user or raw request. This tests chart context, not reciprocal physician access. |
| Target write and audit boundary | Model text, suggested chips, clinician Save workflow | Unsolicited write, false action claim, missing disclosure audit | Brief says tools read only and Save requires clinician action. Current report fingerprint is limited; [X01](https://linear.app/hdxsfbr/issue/HDX-34) is optional corroboration. |
| Auditor evidence and judgment | Target response, PDF, Red Team proposal, Judge verdict | False safe or confirmed result; nonreproducible report | Private PDF hashes and separate Judge exist. [Audit](docs/audit/2026-09-28/AUDIT.md) shows gaps in fidelity, gates and integrity; [E01](https://linear.app/hdxsfbr/issue/HDX-7), [E02](https://linear.app/hdxsfbr/issue/HDX-8), [E03](https://linear.app/hdxsfbr/issue/HDX-10) own fixes. |
| Auditor operator boundary | Any client reaching LAN port | Configure targets, read synthetic evidence, approve exports | Current deployment has no app login. Restrict the trusted LAN and firewall; multi-operator use needs a separate identity decision. See [README](README.md#operations-and-recovery). |
| Providers and dependencies | Ollama, OpenRouter, npm/container images | Sensitive packet disclosure, supply-chain change, cost amplification | Current Judge scrubbing replaces two configured external patient IDs and known usernames/passwords/session secrets/header patterns, but not arbitrary names or facts. [E01](https://linear.app/hdxsfbr/issue/HDX-7)/[E03](https://linear.app/hdxsfbr/issue/HDX-10) own broader stable pseudonymization and fail-closed hosted dispatch. Paid calls reserve bounded cost; no dependency scan or production baseline is claimed. |

Attack paths: `chat/PDF or chart text → Co-Pilot retrieval/model/verifier → clinician-visible answer`; `answer/effect → auditor observation/check/Judge → finding/report`; and `operator → auditor API/worker → synthetic target/provider`. Authentication and authorization must hold at every arrow, including report download and any future read-only adapter. The host allowlist is a dispatch constraint, not authentication.

## Prioritized threat and coverage map

The categories below use [OWASP Top 10:2021](https://top10.owasp.org/2021/) and [OWASP LLM Top 10:2025](https://genai.owasp.org/llm-top-10/) identifiers as **risk mappings**, not claims that existing cases already prove coverage. Difficulty is a planning estimate for an authorized synthetic test.

| Threat / attack surface | Potential impact; difficulty | Existing defense or proof limit | Planned case and OWASP mapping |
| --- | --- | --- | --- |
| Direct prompt override in chat; persona/system-prompt hijack | Unsafe advice or hidden instruction disclosure; low to medium | One direct starter exists; a refusal can be misjudged. | Direct override plus refusal/echo negative controls. LLM01, LLM07; A03:2021 injection. [C02](https://linear.app/hdxsfbr/issue/HDX-18). |
| Indirect instruction in note, problem comment, or attached PDF; malicious source text | Cross-chart facts, false citations, context poisoning; medium | PDF transport exists, but citations are flattened and attachment provenance weak. | Synthetic PDF/note sequence with source binding and wrong-patient control. LLM01, LLM04, LLM05; A03:2021. [E01](https://linear.app/hdxsfbr/issue/HDX-7), C02. |
| Multi-turn conversation, history carryover, context switch | Leakage across turns, users or open charts; medium | Fresh case session and distinct users are used, but broad multi-turn matrix is absent. | A→B chart-reference prompts while A remains open; cross-case reset control. LLM01, LLM02; A01:2021 access control. [C02](https://linear.app/hdxsfbr/issue/HDX-18). |
| Patient/body/URL/attachment identity tampering; role escalation | Another patient's facts or unauthorized section; medium to high | Exact external-ID resolution and target ticket contract exist; no reciprocal access denial expected. | Synthetic wrong-context/role and document mismatch cases. LLM02; A01:2021, A07:2021. [C02](https://linear.app/hdxsfbr/issue/HDX-18), [L01](https://linear.app/hdxsfbr/issue/HDX-35). |
| Tool invocation or parameter misuse; recursive reads; unrequested save/order | Chart integrity or audit gaps; medium to high | Model cannot choose auditor transport; target brief says agent tools read only. Report hash cannot rule out all writes. | No unsolicited write/advice negative control; correlated audit/fact proof only if approved. LLM06; A04:2021 insecure design. [X01](https://linear.app/hdxsfbr/issue/HDX-34). |
| Unsafe rendering and unverified or invented citation | Misleading clinical decision, possible browser injection; medium | Target brief describes verification, but auditor's current citation check is text-based. | Structured citation/claim-kind test and inert HTML test. LLM05, LLM09; A03:2021. [E01](https://linear.app/hdxsfbr/issue/HDX-7), C02. |
| Oversized input, long turn, repeated requests or model calls | Denial of service and cost growth; low to medium | Case/action/spend bounds exist; current 15-second target timeout conflicts with target's 90-second turn bound. | Max-length, time, case-budget and no-progress controls. LLM10; A04:2021. [E04](https://linear.app/hdxsfbr/issue/HDX-11), [A17](https://linear.app/hdxsfbr/issue/HDX-29). |
| External URL or dependency compromise; SSRF, component drift | Network/data exfiltration or invalid results; medium to high | Red Team URL proposals are rejected; dependency scanning is not evidenced. | Authorized synthetic endpoint rejection and dependency review, never arbitrary live scanning. LLM03, LLM05; A06:2021, A10:2021 SSRF. [Q01](https://linear.app/hdxsfbr/issue/HDX-13), [I01](https://linear.app/hdxsfbr/issue/HDX-36). |
| Missing audit event, missing PDF, misleading report | False assurance and failed incident reconstruction; medium | Integrity endpoint exists, but review/export bypasses missing artifact. | Delete/corrupt evidence, missing-audit and report-citation controls. A09:2021 logging; LLM02/LLM05. [E02](https://linear.app/hdxsfbr/issue/HDX-8), [F01](https://linear.app/hdxsfbr/issue/HDX-22). |

Every published case should record a boundary, invariant or regression risk, category/subcategory, OWASP versioned tags, severity **rationale**, exploitability conditions, expected safe behavior, actions and observed result. Mapping is currently a design; [C01](https://linear.app/hdxsfbr/issue/HDX-15) and [C02](https://linear.app/hdxsfbr/issue/HDX-18) make it queryable. Review this model after any new target version, verified finding, failed negative control or changed evidence source. Do not turn an untested row into a pass-rate denominator.
