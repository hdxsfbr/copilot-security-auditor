# Users and justified workflows

The first user is the **single authorized security operator** responsible for a synthetic Clinical Co-Pilot target. The operator configures two distinct synthetic clinician/chart assignments, sets a bounded case or adaptive run, watches failures and spend, inspects exact evidence, decides uncertain findings, and authorizes a redacted report. This is the current trust boundary: the auditor has no application login, so anyone with LAN access has operator power. The operator must keep the service on a restricted trusted LAN and the target host allowlist narrow. The application must not be treated as a multi-tenant clinical security service. [README](README.md#operations-and-recovery) describes current operation; [U02](https://linear.app/hdxsfbr/issue/HDX-12) and [U03](https://linear.app/hdxsfbr/issue/HDX-17) own the planned recoverable workflow.

| User and decision | Concrete use case | Why automate this part; human boundary |
| --- | --- | --- |
| Security operator: decide what to test | Select current target/version, inspect untested categories, choose a synthetic case or bounded adaptive seed set, preview role/cost limits. | Manual prompting cannot consistently cover versions, variants and recurring schedules. Automation proposes and executes only bounded authorized actions; operator provides target and spend authority. Current coverage is global and incomplete; [V01](https://linear.app/hdxsfbr/issue/HDX-24) and [A17](https://linear.app/hdxsfbr/issue/HDX-29) add scoped prioritization. |
| Security operator: judge a candidate | Open exact run/case/turn, compare expected vs observed behavior, source metadata, deterministic checks and Judge rationale; confirm, reject or leave unresolved. | A machine can sort complete, repeated evidence and surface contradictions, but a clinical fact, chart effect or causality claim may exceed black-box proof. Human review resolves uncertainty; [E01](https://linear.app/hdxsfbr/issue/HDX-7), [E02](https://linear.app/hdxsfbr/issue/HDX-8), [E03](https://linear.app/hdxsfbr/issue/HDX-10) repair current evidence/gate defects. |
| Security operator: keep fixes fixed | Replay a confirmed synthetic attack on an explicitly identified target version, compare the same boundary and note fixed, recurring, resurfaced or unknown. | Repeated exact replays are tedious and easy to omit after deployment. A changed model answer alone cannot prove a fix; [G01](https://linear.app/hdxsfbr/issue/HDX-26) and [G02](https://linear.app/hdxsfbr/issue/HDX-27) own suite identity and version comparison. |
| Co-Pilot engineer and security reviewer: act on a report | Receive a minimal redacted sequence, expected/observed facts, source references, severity reasoning, remediation and fix-validation evidence. | Consistent drafting saves reviewer time and makes failures comparable. The operator approves the exact report revision before sharing; the current JSON export is a placeholder, with [F00](https://linear.app/hdxsfbr/issue/HDX-39), [F01](https://linear.app/hdxsfbr/issue/HDX-22), [F02](https://linear.app/hdxsfbr/issue/HDX-23) owning replacement. |
| Clinical safety stakeholder: assess trust | Ask which guarantees were exercised on this version, whether a confirmed chart-context leak or unsolicited action recurred, and what remains untested. | Versioned evidence and explicit unknowns are more reliable than anecdotes or a one-time demo. This stakeholder reviews results; they do not operate the synthetic test credentials. [V02](https://linear.app/hdxsfbr/issue/HDX-25) owns the view. |

The Co-Pilot's physician is the **target application's user**, not an auditor account. The clinician may open another chart with legitimate rights, but a conversation bound to patient A must not answer from patient B's clinical facts. No test should demand that OpenEMR revoke legitimate chart access merely to make a Co-Pilot case pass. The attack channel remains user-facing chat or synthetic PDF. The optional read-only adapter, if an exact contract is approved, is evidence-only and disabled by default; it is not an alternate attack channel.

Automation is justified where it provides repeatable execution, preserved provenance, bounded mutation, recurring regression checks, and cost/event accounting. It is not a substitute for target authorization, clinical interpretation, report publication approval, or proof of independent peer integration. The intended operator workflow and its current limitations are recorded in the [audit](docs/audit/2026-09-28/AUDIT.md) and [delivery plan](docs/implementation/audit-delivery/PLAN.md).
