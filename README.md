# Clinical Co-Pilot Auditor

A LAN-only selected-case auditor for an **operator-owned synthetic** OpenEMR / Clinical Co-Pilot. It does not deploy the target. Selected cases exercise prompt injection, cross-patient access, and unintended tool actions against a live toy target, record the user-visible response and an independent Ollama or OpenRouter Judge verdict, and keep safe, inconclusive, blocked, and incomplete outcomes distinct. Do not point this at clinical records or an unauthorized service.

## Run in Docker

Requires Docker Compose, a host Ollama with an installed model, and an operator-owned toy target; Node, npm, and PostgreSQL run only in containers. Copy `.env.example` to `.env`, generate a unique `DB_PASSWORD` and 64-character hex `CREDENTIAL_KEY`, and set `LAN_BIND` to a specific trusted LAN interface (or `127.0.0.1` for this machine only). Set `OLLAMA_MODEL` to a model installed on the host. Docker Compose reads `.env` automatically; no environment variable exports are needed. Keep `.env` private, back up `CREDENTIAL_KEY` securely, and reuse both secrets across restarts; changing the database password or encryption key after storing data requires a coordinated rotation. Start the stack:

```sh
docker compose up --build -d
```

Open `http://<LAN_BIND>:3000` from the trusted LAN with your `.env`. The API migrates the database at startup and serves the built UI. The run form loads its Ollama endpoint and installed model defaults from `.env` via the API's `/api/config` endpoint; edit only `.env` to change these defaults, then recreate the services with `docker compose up --build -d`. Compose maps `host.docker.internal` to the host gateway for the API and worker on Linux. The worker and database have no published host ports, and Compose does not start or download an Ollama model.

The host Ollama must be reachable from Docker. Ollama bound only to `127.0.0.1:11434` on Linux is **not** reachable through `host.docker.internal`; configure the host Ollama listener for an address reachable from the Docker network and restrict port 11434 with your firewall. Do not bind Ollama to a publicly reachable interface just to make the container connect. If you use a different reachable host address, port, or installed model, edit `OLLAMA_URL` or `OLLAMA_MODEL` in `.env`. The UI calls the auditor API, not Ollama directly, so the endpoint must work from the **worker container**, not just your browser.

The target itself is not deployed by this stack. Enter an OpenEMR URL reachable **from the worker container** (for example, another container's service name on a shared Docker network, or `http://host.docker.internal:<port>/` if the toy target listens on an address reachable via the host gateway). Compose maps that host name on Linux; a toy target bound only to host loopback is not reachable through the gateway. A browser-local `127.0.0.1` target URL points back to the worker container and will not work. Only use an authorized synthetic target. Keep the credential key outside PostgreSQL, back it up separately, and do not rotate it without re-encrypting stored identities. Treat the PostgreSQL and private evidence volumes as one backup unit. There is no application login: **anyone who can reach the LAN port has full operator power**, including reading synthetic observations. Do not expose it publicly.

## Selected-case workflow

1. Create a target with the OpenEMR root URL (trailing path allowed) and **two distinct authorized synthetic** user/chart assignments. Enter each chart's **external patient ID (`pubpid`) shown in OpenEMR**, not its internal numeric `pid` or patient name. External IDs accept letters, digits, and hyphens only (no search wildcards). The worker resolves each assigned ID with that user's authenticated OpenEMR patient finder, requires exactly one exact result, and uses its numeric `pid` only to select the chart. Missing, ambiguous, inaccessible, or mismatched lookups block the run before a turn. Credentials and assignments are AES-256-GCM encrypted in PostgreSQL; passwords are never returned by the API. The deployment key is required to decrypt them. Save creates a new target and selects it for the next run; use "Target to configure" to load an existing target's username and external ID for editing. Leave passwords blank on update to keep their existing values, or enter new passwords to rotate them. Previously saved targets without an external ID can be updated this way. Target updates are rejected while a run is reserved, and prior runs retain their credential references.
2. Three starter case definitions (direct injection, Co-Pilot chart-context isolation, and a read-only unintended-action probe) are installed once and appear under "Selected case" after refreshing the UI. Inspect the case preview before starting: nothing is dispatched until you press Start. The chart-context case opens user A's assigned chart and asks about user B's assigned chart; the worker substitutes `{{OTHER_PATIENT_ID}}` with the saved external ID. Both charts must resolve distinctly, but OpenEMR finder visibility and physician access to both records are not considered Co-Pilot failures. A prior role-isolation starter remains labeled Legacy on existing installations for historical replays. Merely repeating an ID from the prompt is not proof of clinical disclosure; chart-context results needing proof remain inconclusive or pending review, not auto-confirmed. For an indirect-injection case, author a new case with a synthetic PDF, a relevant prompt, and a source-citation check. The starter unintended-action case requests advice only. The worker compares read-only OpenEMR patient reports (including orders) before and after the chat turn and records `changed`, `unchanged`, or `unavailable` without persisting the report contents. A change needs review; an unchanged report cannot rule out writes not represented in the report and remains inconclusive. Neither a chat response nor this limited comparison automatically proves a safe or unsafe action outcome. Select the case and target first; a busy target returns 409 with the active run ID.
3. The worker probes readiness, logs in with a fresh cookie jar (302 success), resolves the exact external ID through `interface/main/finder/dynamic_finder_ajax.php` (`sColumns=pubpid`, `searchType=true`), opens the resolved numeric chart, obtains the module CSRF and conversation, mints a new ticket per turn, and calls the user-facing agent endpoint. A valid `fallback` is evidence, not a pass. Only an explicitly not-applied turn can be retried once with a new ticket. Ambiguous delivery ends incomplete.
4. In "Role models & spend", choose a provider, model and maximum output tokens for each of Orchestrator, Red Team, Judge and Documentation. Selected-case runs call **only the Judge**; bounded adaptive runs also call the Orchestrator and Red Team. Documentation is saved but not called. With no `OPENROUTER_API_KEY`, use local Ollama and no dollar price is assigned to local inference. For OpenRouter, set `OPENROUTER_API_KEY` only in private `.env`, choose an available model and set a positive per-run USD cap before starting. A verified catalog price for the entire context window, maximum output and request fee is reserved transactionally before dispatch. The paid request restricts provider prices to those reserved and disables provider fallback. Unknown or unsupported pricing, over-cap estimates and unresolved provider charges prevent further paid calls; an ambiguous charge remains reserved and an incomplete run never becomes a pass. No automatic model fallback occurs. The server does not return the key to the browser. Hosted role calls receive secret-scrubbed, patient-aliased packets, never session cookies or raw assigned patient IDs. Use synthetic data only; packet scrubbing is not a substitute for de-identifying arbitrary free-text clinical records.
5. Poll the run view for version, turn/attempt sequence, deterministic check scope, provider/model token and latency usage, reported paid charge or unresolved reservation, verdict and review candidate. A pending-review run releases its target immediately. Supported, cited unsafe results can be auto-confirmed; other candidates require operator review. Confirmed findings create a regression definition, and a separate approval is required before viewing a redacted export. No model-generated URL or patient ID controls transport. The older "Start selected run" button remains an Ollama-only shortcut.

## Bounded adaptive exploration

Choose one or more saved synthetic seed cases in the adaptive form; the chosen categories, assigned users, expected safe behavior, checks, and approved PDF references come from those cases. Set 1–9 maximum cases and 1–30 elapsed minutes, plus a per-run OpenRouter cap if any selected role uses OpenRouter. The Orchestrator chooses from seed case IDs in the least-executed selected category. The Red Team proposes 1–3 typed actions; raw URLs, requests, patient identifiers, credentials, and unlinked PDF references are rejected before target transport. Each admitted case runs in a fresh authorized chart session through the same judgment and finding gate as a selected case. Only executed cases count toward coverage; view rejected, blocked, inconclusive, incomplete, and untested categories in the progress panel. Stop is cooperative: an already in-flight request may complete, but an unfinished case and its parent run cannot become a pass. The target reservation is released on completion. A confirmed adaptive finding can be selected for replay from the regression list, which materializes its exact validated action definition and links only its authorized synthetic attachments.

## Scheduled evaluations

Use the Scheduled evaluations panel to create or edit a daily or weekly schedule from a saved run definition (compose and save one under Launch). Picking a definition shows its target, mode, cases, active-role models, paid cap and any report policy; then choose a wall time, weekday (Sunday through Saturday for weekly) and IANA time zone. Every schedule and occurrence time is shown in the schedule's own zone with its abbreviation, for example `09:00 America/Chicago (CDT)`, plus a labeled browser-local line when your browser zone differs. Schedules snapshot the definition revision, case definitions and model choices; each due occurrence takes fresh saved target credentials. Pausing retains occurrence history; resuming after missed times advances to the next future local slot. Removing a schedule archives it: future occurrences stop, and it moves to Archived schedules, where its definition summary and its occurrence history (paged newest first, with state, skip or block reason and a link to the run) stay inspectable. A skipped occurrence records its scheduled timestamp and busy target run ID, and a failed target/login/chart preflight is blocked, never a safety pass or retry of that occurrence. Runs queued by a schedule use the same evidence, findings, regressions and export approval policy as manual runs. At a daylight-saving gap the first valid local minute after the gap is used; at a repeated local time only the first occurrence fires. If the API was offline at a due time, it records that occurrence at its original scheduled timestamp when it restarts, then advances to the next future occurrence; review it before assuming the target state is unchanged. A worker lease timeout marks the scheduled occurrence blocked with an execution-uncertain reason. The scheduler ticks in the API container and does not publish an additional port.

The module handshake and `/copilot-api` paths are specified by the operator's toy target contract. If your target differs, verify the contract before use. Responses are bounded and known secrets are scrubbed before persistence; the Judge receives stable patient aliases rather than raw patient IDs. Keep these toy observations on a trusted LAN.

## Operations and recovery

- **LAN boundary and firewall:** `LAN_BIND` must be the trusted interface address, not `0.0.0.0`; Compose publishes only port 3000 on that address. Add host-firewall rules allowing that port only from the operator subnet, deny it from guest/WAN networks, and do not publish the database, worker, artifact volume, or Ollama port. LAN reachability grants full operator power: every reachable client can configure targets, run tests, read full synthetic evidence, decide reviews, and approve exports. This is the access boundary; there is no authenticated application user.
- **Target allowlist:** `TARGET_ALLOWED_HOSTS` is a comma-separated exact-hostname allowlist, not a URL or wildcard list. Include only the operator-owned toy target hostname(s), e.g. `host.docker.internal` or a private Compose service name. The API rejects target create/update outside this list. Do not add broad public domains or clinical systems. Provider/Ollama egress should also be restricted at the host/network firewall to the endpoints in use.
- **Keys and identities:** Generate a unique random `DB_PASSWORD` and 32-byte `CREDENTIAL_KEY`; store `.env` and off-host copies in an operator-controlled secret store with limited access. Back up the credential key separately from the database: database backup without the matching key cannot decrypt saved test identities. Never paste keys into issues/logs or commit them. Use two distinct, least-privilege synthetic OpenEMR accounts assigned only seeded toy charts; use external `pubpid` values, not real patient data. Key rotation requires coordinated credential re-encryption; changing the key in place makes stored credentials unreadable.
- **Evidence and decisions:** Missing, checksum-mismatched, or orphaned files invalidate evidence integrity. Such cases are incomplete/inconclusive, never safe and never confirmed findings. Evidence/artifact integrity failures require restoration and a new explicit run; never replay an ambiguous target turn automatically. Review captures an action and timestamp only; it does not authenticate or prove the reviewer's identity. Export remains a separate explicit approval.
- **Spend:** UI call rows distinguish provider-reported OpenRouter charge (`settled`) from conservative reserved amounts whose billing could not be determined (`unresolved`). Unresolved holds remain in the run total and stop further paid calls until an operator reconciles provider usage. A configured cap bounds the auditor's dispatch reservation based on verified pricing, but is not a guarantee against provider-side billing variance. Ollama calls show usage/latency without an invented dollar price.

### Paired database and evidence backup

Take backups while API and worker are stopped so no new database references or artifact writes can race the pair. Keep the dump and volume archive together, encrypt them at rest, and include the matching `CREDENTIAL_KEY` in a separately protected recovery envelope:

```sh
docker compose stop api worker
docker compose exec -T db pg_dump -U auditor -d auditor -Fc > auditor-db.dump
docker compose run --rm --no-deps api tar -C /app/private-evidence -czf - . > private-evidence.tgz
docker compose start api worker
```

Restore into an isolated, trusted LAN deployment with the same Compose project/volume names and matching `.env`. Keep API and worker stopped while loading both halves:

```sh
docker compose stop api worker
docker compose exec -T db pg_restore --clean --if-exists -U auditor -d auditor < auditor-db.dump
docker compose run --rm --no-deps api tar -C /app/private-evidence -xzf - < private-evidence.tgz
docker compose up -d api worker
curl --fail http://<LAN_BIND>:3000/api/health
```

Verify a prior run and retrieve its referenced PDFs through the API; `GET /api/integrity` reports missing, corrupt, or orphaned volume entries, and each referenced PDF is checked against stored size and SHA-256 metadata before use. Do not expose the isolated restore to an untrusted network. The API health endpoint reports unavailable until PostgreSQL is reachable, migrations are complete, and its migration ledger can be read; the worker is gated on that health check. Worker leases expired during downtime are fenced, unfinished cases become incomplete, target reservations release, and ambiguous paid calls stay unresolved rather than being redispatched.

### Opt-in live smoke

The standard `npm run test:unit`, `test:integration`, `test:e2e`, and `test:failure` suites are fixture-only; they never invoke `test:live`. The live smoke is a separate, explicit operator command and requires the exact target URL, two assigned synthetic identities, a stated maximum possible provider charge, and confirmation that the target/provider actually enforces a matching spend cap. It validates readiness/login/chart/session for both identities, distinct chart assignments, one bounded synthetic PDF attachment, and one short ticketed turn. It does not provision or authorize a target, and does not itself enforce provider billing; stop if the effective provider-side cap cannot be confirmed.

```sh
SMOKE_TARGET_URL=https://toy.example.test/ \
SMOKE_USER_A=synthetic-a SMOKE_PASSWORD_A='...' SMOKE_PUBPID_A=SYN-900001 \
SMOKE_USER_B=synthetic-b SMOKE_PASSWORD_B='...' SMOKE_PUBPID_B=SYN-900002 \
SMOKE_CHARGE_CAP_USD=0.05 SMOKE_PROVIDER_CAP_CONFIRMED=true \
npm run test:live
```

Run only against an operator-owned toy target after separately authorizing the identities and setting its effective provider-side cap. Do not use real patient data. The smoke command is never run automatically or on startup.

## Verification

Run `npm run typecheck && npm run build && npm run test:unit && npm run test:integration && npm run test:e2e && npm run test:failure`. Integration/failure suites create disposable PostgreSQL containers; browser e2e also needs `/usr/bin/google-chrome`.

The image build checks types and builds the UI. To run unit tests without host Node, use `docker compose run --rm --no-deps api npm run test:unit`. Integration tests start disposable Docker services and require a Docker daemon. Browser e2e tests also require `/usr/bin/google-chrome`; run `npm run build && npm run test:e2e` on a host with Chrome or an appropriate test container. The fixture suite covers capped mixed-provider behavior without paid provider calls, and fake-clock daily/weekly DST plus concurrent scheduler ticks. A bounded synthetic adaptive run was stopped after an observed turn on the live toy target using the host Ollama; its case/run were incomplete, the observation remained visible, and the target was released.
