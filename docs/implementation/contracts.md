# Internal agent handoffs, version 1

K01 publishes the three internal envelope schemas in [`contracts/v1`](../../contracts/v1/) from the Zod authority in [`packages/contracts/src/agent.ts`](../../packages/contracts/src/agent.ts). The worker uses the Orchestrator→Red Team and Red Team→Judge handoffs. Judge→Documentation is a **future input contract** for [F01](https://linear.app/hdxsfbr/issue/HDX-22/f01-implement-evidence-grounded-finding-metadata-and-report-drafting); no Documentation role is invoked by K01. These contracts do not prove communication with an independent peer service; [I01](https://linear.app/hdxsfbr/issue/HDX-36/i01-complete-peer-integration-proof-and-security-review-evidence) owns that evidence.

Every envelope has `channel`, `status`, and a strict header: `version: 1`, a fresh `messageId`, optional `parentMessageId`, and `runId`, `caseId`, `attemptId`. The header binds a message to one execution. For a selected case, the worker uses the run ID and lease generation for the attempt ID. For an adaptive case, it adds the ordinal. All handoffs for that attempt reuse this ID; a new lease generation cannot consume the prior attempt's message. The Orchestrator success contains the selected seed ID, category, remaining case/time bounds and optional history references. The Red Team success contains the executed, provider-projected Judge packet, policy version and evidence references. The worker validates the selection before beginning an adaptive case, validates a Red Team proposal before target execution, and validates the executed handoff before pricing or reserving the Judge model. The model consumer validates it again before transport. The model's raw JSON is not an agent envelope and cannot supply a trusted header.

Evidence references are composite `(runId, attemptId, ref)` records. Each records observation version and completeness; v2 also records the target turn ID. v1 observations remain readable with completeness `unknown`, not inferred complete. The Red Team→Judge validator requires unique observation refs and turns, unique action turns and evidence refs, and one-to-one mapping among them. A PDF action must carry its artifact type and uploaded source ID, matching the v2 observation attachment; a chat action cannot carry PDF fields. Check references must point into that packet. The consumer applies the existing 100,000-character packet cap. Header/context mismatch, unsupported version, malformed shape and inconsistent evidence fail with typed `AgentContractError` before provider transport. A schema-valid envelope alone does not prove a claim or broaden the E03 safe or automatic confirmation gates.

| Channel | Success or nonfinding meaning | Known error handling |
| --- | --- | --- |
| Orchestrator→Red Team | Select one allowed seed under the stated bounds; selection does not authorize arbitrary actions. | An error carries a typed code/stage and, when present, deadline facts. The current adaptive worker conservatively limits the run on selection failure. |
| Red Team→Judge | Executed prompts, observed target evidence, deterministic checks, effect scope, limitations and stable refs are passed to the Judge. | Runtime worker events contain typed `target_unreachable`, `target_boundary_unavailable`, `budget_exceeded`, `reservation_unavailable`, `judge_timeout`, or `provider_unavailable` envelopes where those conditions are observed. Before scheduled adaptive preflight selects a case, the event contains a validated `contractError` without an invented case ID. Deadline stage, elapsed/limit milliseconds and `attempted` are retained; an attempted paid timeout remains an unknown charge under E04. |
| Judge→Documentation | `ok` requires an automatically confirmed outcome or a separately human-confirmed pending-review outcome. `no_findings` means no supported finding was produced; its source outcome may be safe, inconclusive, incomplete or blocked and the status itself makes **no safe assertion**. Regression is explicit (`new`, `recurring`, `fixed`, `resurfaced`, `unknown`, or `not_applicable`). | F01 must validate this envelope at both ends and implement report-job error mapping; K01 supplies only its schema and parser. No report or regression verification is implied by this schema. |

The existing E03 deterministic policy remains the only worker authority for `safe` and `auto_confirm`. A quoted response does not prove unseen chart access or writes. A Documentation `ok` envelope requires evidence refs, a policy trace and a separate confirmation basis. F01 must compare these fields with persisted decisions and approved evidence before report creation. A regression label is a typed claim to verify against earlier findings, never proof by itself.

Regenerate schemas with `node --import tsx contracts/generate.ts`; `tests/contracts/agent.test.ts` fails if committed JSON drifts from the Zod source. Compatible optional fields can be added only when old readers retain their meaning. A changed required field, enum meaning, evidence semantics or eligibility rule requires a new schema version and documented migration; silently reinterpreting v1 messages is disallowed. Existing persisted observations and policy events remain v1/v2 as recorded and are not relabeled by these handoffs. No cross-process delivery, independent-agent execution, live target correctness or model accuracy is established by the synthetic contract fixtures.
