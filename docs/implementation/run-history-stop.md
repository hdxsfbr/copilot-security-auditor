# Run history, exact case detail, and cooperative stop

`GET /api/runs?limit=25&cursor=...` returns newest runs across manual and scheduled launches as `{items,nextCursor}`. Limits are 1–100. The opaque versioned cursor holds the exact PostgreSQL UTC microsecond timestamp and UUID, so rows created in the same millisecond remain stable across pages. Invalid cursors return 400. The `(created_at DESC,id DESC)` index supports the order. History shows status, outcome, stop state, recorded target name/version, selected case family/version or adaptive categories, and schedule occurrence. It does not return credential references or target base URLs. A missing historical target name or version remains unknown.

`GET /api/runs/:id` retains its existing fields and adds immutable target and selected case snapshots or adaptive seed snapshots. It never substitutes the target's or case's current editable record for saved run content. `GET /api/runs/:id/cases/:executionCaseId` binds an adaptive execution case to the run and distinguishes the saved source seed from its admitted action definition. A proposed or rejected case can have no admitted definition. `executed` records whether a target action was attempted; an admitted definition alone is not execution proof. Newly emitted adaptive case events carry a worker-owned `executionCaseId` and can be linked exactly. Historical events without the tag have unknown case linkage and are not assigned by timing or ordinal guesswork.

`POST /api/runs/:id/stop` returns 202 for an active selected or adaptive run. A queued stop commits an incomplete terminal run, a scheduled occurrence reason, and release of that run's target reservation together; the worker cannot claim it. A running stop records a request and leaves the lease, target reservation, and paid call holds in place while in-flight work settles. Selected and adaptive workers check before each target turn, after uploads, before Judge, and between model reservation and dispatch; they will not begin another turn after observing the stop. Calls proven never sent may settle at zero. Attempted or ambiguous paid calls retain their unresolved hold until reconciled.

Claim, stop, and finish serialize on the run row. Finish uses the effective stored outcome for assessment, candidate creation and occurrence state; a stop that wins cannot create a candidate from a late Judge result. If finish wins first, a later stop reports no active run. Existing lease expiry still marks reserved paid calls unresolved and releases the target after terminalization. A target-busy 409 includes the active run ID, which resolves through exact run detail.
