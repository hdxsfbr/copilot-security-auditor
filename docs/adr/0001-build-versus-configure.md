# ADR 0001: Build the clinical evidence workflow; configure existing scanning tools where they fit

- **Status:** accepted design for B01; implementation gaps remain tracked below.
- **Date:** 2026-09-29.
- **Context:** The [AgentForge PRD](../../docs/Week%203_AgentForge_PRD.pdf) requires a build-versus-configure defense before agent work. The product must test an authorized synthetic, chart-bound Co-Pilot through chat/PDF, preserve evidence, independently judge outcomes, replay regressions and publish approved clinical-impact reports. A generic prompt score cannot prove a cross-chart fact or chart write.

This is a **documentation-only desk comparison** of primary vendor/project material. We did not install, license, benchmark or run any product against the target. “Does not replace” below is an inference from the required workflow and each tool's documented primary function, not a claim that the tool cannot be extended.

| Option | Documented useful capability | Decision for this bounded project |
| --- | --- | --- |
| [Burp Suite Scanner](https://portswigger.net/burp/documentation/scanner) | Crawls and audits web traffic, including stateful application paths. | Configure separately for permitted web/API security tests if authorized. Its web vulnerability output would still need the Co-Pilot's exact chart conversation, source semantics and finding evidence gate before it can support a clinical AI claim. Do not turn on broad scanning through this auditor. |
| [OWASP ZAP Automation Framework](https://www.zaproxy.org/docs/automate/automation-framework/) | YAML-controlled authenticated web/API scanning and job tests. | Configure for conventional web/API checks in a separate authorized scope. It does not supply the project's clinical fact ground truth, versioned Judge policy or report approval by itself. |
| [Semgrep Code](https://semgrep.dev/docs/category/local-and-cli-scans) | Static source scanning with rules. | Useful for this auditor's own code/dependency review and for a target only when its source is separately authorized. No target source is available in this task; static findings cannot substitute for user-visible exploitation evidence. |
| [garak](https://github.com/NVIDIA/garak) | Open LLM probes, generators and detectors across many weaknesses. | Candidate source of synthetic prompt ideas and comparative detector checks. A model-level failure rate cannot by itself establish a chart-bound Co-Pilot disclosure, source provenance or write effect. An adapter would need the same admission and evidence policy. |
| [Promptfoo red teaming / Enterprise](https://www.promptfoo.dev/docs/enterprise/red-teams/) | Documented generated app/agent attacks, custom flows, grading and reports. | Strong configure-first comparator for later evaluation. Inference: the project's exact OpenEMR session/ticket/PDF protocol, synthetic identity binding, independent evidence limits and operator-approved report revision still need custom integration and validation. No product trial or price comparison has been made. |
| Existing [LangGraph case flow](../../apps/worker/src/process.ts) + PostgreSQL | In-process observe→judge state sequencing; existing durable reservation, lease and accounting code. | Retain and extend. Build custom role envelopes and deterministic policy around these foundations; do not replace tested persistence to satisfy an agent-count label. |

**Decision.** Keep the custom TypeScript transport, repository and deterministic evidence gate because they encode target-specific authority and proof. Configure Ollama or OpenRouter per active role; retain LangGraph only for bounded case sequencing. Orchestrator, Red Team, Judge and Documentation remain separate decision contexts with typed inputs/outputs and no shared model authority over credentials, target dispatch, checks or publication. Conventional DAST/SAST and LLM probe tools may complement the platform after authorized scope review; no current scanner result is imported as a confirmed finding.

**Consequences and validation.** The custom workflow incurs maintenance cost and must prove its own Judge accuracy, response completeness, contract compatibility, rate/cost bounds and report utility. [K01](https://linear.app/hdxsfbr/issue/HDX-38) publishes versioned role schemas, [E03](https://linear.app/hdxsfbr/issue/HDX-10) calibrates judgment, [F00](https://linear.app/hdxsfbr/issue/HDX-39) and [F01](https://linear.app/hdxsfbr/issue/HDX-22) implement bounded Documentation, and [Q02](https://linear.app/hdxsfbr/issue/HDX-30) verifies the complete fixture workflow. Revisit this decision if a configured product demonstrates the same chart/PDF provenance, false-confirm control, exact-version regressions and operator approval with less custom risk. This ADR is not a measured comparison.
